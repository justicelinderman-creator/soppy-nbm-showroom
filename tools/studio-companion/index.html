One Studio tool / Two complementary workflows

01 / SHIPCHECK — READ ONLY

Find the thing worth checking.

The existing scene-audit engine can review a Workspace or explicit selection, show advisory findings, jump to an object, and compare a complete scan against a baseline. It covers heuristic risks like invisible colliders, giant loose parts, zero-range prompts, constraints, effects and default spawns.

Not a frame-rate profiler, script security scanner, automatic game builder or guarantee that your game has no bugs.

02 / QUICKOPS — PREVIEW BEFORE EDIT

Skip repetitive Explorer clicks.

In the new private candidate, select specific objects, preview numbered names or property updates (Anchored, CanCollide, CastShadow), and explicitly apply only the selected changes using a native Studio Undo recording. A few audit findings can suggest an edit preview; they never auto-fix the place.

Only the selected supported instances are considered, up to 200. Renaming can break name-based script references; it does not rewrite code. Real dock/Undo acceptance is still pending.

THE ROBLOX UPDATE
CHECKLIST.

Before your next Studio publish, inspect these eight areas manually. They aren't a replacement for gameplay tests.

01 — Invisible geometry

Make sure fully transparent collidable parts are intended blockers, hitboxes, or boundaries—not forgotten obstacles.

02 — Large, loose objects

Inspect large unanchored collidable objects. Check intended physics and constraints before deciding to anchor anything.

03 — Player interaction

Test enabled ProximityPrompts, activation distance, visibility and reach with actual player movement.

04 — Spawn behavior

Check spawn spacing or your custom spawn code in a real playtest, rather than relying only on default SpawnLocation counts.

05 — Constraints and attachments

Review required connection endpoints on mechanical parts and verify the desired behavior in Play mode.

06 — Effects and geometry budgets

Check particle rates and large part counts, then profile on your actual target devices. Heuristic counts alone aren't FPS measurements.

07 — Name-based code references

Before batch renaming assets, search your own code for hardcoded instance names and verify the affected systems afterward.

08 — Record the before and after

Save a clean version and compare the same test scenarios after each update. Verify what changed and what still needs attention.
