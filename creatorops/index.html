The actual source-built design

TWO WORKFLOWS.
ONE DOCK.

01 / ShipCheck

Inspect before you publish.

Review Workspace or the selected scene for advisory flags such as unexpected invisible colliders, large loose parts, prompt settings and expensive particle use. Navigate to findings, compare complete scans against a baseline and export reports locally.

The audit does not inspect scripts for bugs, measure actual frame rate, or certify a game as bug-free.

02 / QuickOps

Make bounded changes, on purpose.

Preview numbered rename, anchor selected parts, disable collision, or disable shadows. Before applying, inspect exactly which selected objects and properties would change. A successful edit is designed to create one Studio Undo history entry.

At most 200 explicitly selected objects. No recursive edits. Renaming may break name-based script references; scripts are not automatically refactored.

Read-only audit→ Select finding→ Preview edit→ Confirm Apply→ Undo or rescan

This workflow is a functional source-level candidate, not a recorded screenshot or completed native user trial. It competes with existing tools; user feedback will determine whether it solves enough real problems.

A SMALL RELEASE
CHECKLIST.

Roblox creators can check these areas manually today. A flag is a reason to investigate—not an automatic mistake.

These are editorial reminders, not proof of a game passing performance or security tests.

  1. Look for invisible collidable parts that could surprise players. Some are deliberate hitboxes; verify intent.
  2. Review large loose parts and confirm they are meant to move under physics.
  3. Test prompts from real player distances and make sure their settings match the interaction.
  4. Inspect particle-heavy areas in a native playtest, especially on lower-end devices.
  5. Verify spawn positions and movement paths with actual players, not only Explorer values.
  6. Before batch renaming or changing collisions, preserve a version and confirm Undo/Redo restores the exact objects.
