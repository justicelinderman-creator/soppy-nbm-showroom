Before we start

A few useful
answers.

What should I send first?

A short explanation of the workflow, one failure you can reproduce, and the behavior you expected. Include your n8n version and hosting type if known. Keep passwords, API keys and private customer records out of email.

Can you promise a delivery date now?

We confirm a realistic date after reviewing the workflow and access requirements. Sending a brief does not reserve time or create a payment obligation.

Will you work directly in production?

Access, test environment and deployment responsibility are part of the written scope. Any live change needs an agreed test and rollback approach. We start with sanitized evidence wherever possible.

How do payment and revisions work?

We agree the scope, acceptance criteria, delivery date, payment and refund terms in writing before payment. The baseline includes one revision within that scope. Payment details are shared privately after agreement.

What if I need a new system or broader support?

Describe it in the brief so we can assess fit and provide a separate scope. The $200 pilot covers one reproducible failure class in one existing workflow.
